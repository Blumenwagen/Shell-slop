# QML Shellcraft Audit — 2026-08-10

Scope: full repo. Focus: (a) does it actually teach QML/Quickshell from zero, (b) usability, (c) the reported "clear conditions never explained" problem. Findings verified against source with file:line references.

---

## A. The headline problem: the graded content is not the taught content

### A1. The 134 "atlas" quests are template-generated from 28 shared recipes
`app/course/atlas.ts` maps 134 narrative blueprints onto only **28 `Recipe` objects** (`atlas.ts:246-478`) that supply starter code, solution code, and the pass checks. Per-quest authored content is ~4–6 sentences (objective/mechanism/failure/analogy). Everything else:

- `story` — one identical template for all 134 quests, only names substituted (`atlas.ts:930`).
- `rules` — templated for the 110 quests of campaigns II–V (`atlas.ts:551-555`); only 24 campaign-I quests have hand-written rules.
- `explanation` — one authored sentence per paragraph glued to boilerplate identical across all quests (`atlas.ts:931-935`).
- `starter`/`solution`/`checks` — verbatim from the shared recipe (`atlas.ts:939-941`). The battery, backlight, audio-device, volume, MPRIS, media-transport, Wi-Fi, Bluetooth, VPN, OSD, and workspace quests (18 quests on recipe `domain-view`) all ship the **identical exercise**: `Text { text: "<label>" }` starter (`atlas.ts:402`) and a generic `service.status === "ready"` solution — regardless of the domain the quest claims to teach.

Recipe reuse counts: domain-view ×18, visual-policy ×14, validation ×11, service ×8, qml-contract ×7, notification ×7…

**Structural, not incidental:** the `Blueprint` type has no `checks` field (`atlas.ts:204-222`), so checks *cannot* reflect quest-specific content. Examples of the resulting mismatch:
- `grammar-error-compass` (brace-repair lesson) is checked on typed/readonly properties and `root.` bindings (`atlas.ts:252`) — nothing about braces.
- `binding-repair-clinic` (binding-loop lesson) — same generic checks, nothing about loops.
- `value-toolchest` promises colours/URLs/enums/lists/null; recipe `qml-values` (`atlas.ts:258-260`) contains none of them.

### A2. In the 26 legacy quests (`app/page.tsx`), checks require untaught syntax
- **`reactive-bindings` (quest 4, a mandatory boss gate)** — check 3 (`page.tsx:298`) requires `onClicked: … = !…`, i.e. a `MouseArea` + event handler + `!` negation. None of this appears in the quest's explanation, anatomy, terms, or starter (`page.tsx:243-276`). `MouseArea` is formally taught **three quests later** (`signals-and-functions`, `page.tsx:420-474`). This is the exact "clear condition never explained" failure, on a gate quest.
- `theme-tokens` (`page.tsx:820`) — checks require the *consumption* pattern (`required property QtObject theme`), which appears only in the solution, never in the taught anatomy (`page.tsx:788-796`).
- `panelwindow-edges` (`page.tsx:919`) — requires boolean anchors (`top: true`) after the course trained object-reference anchors (`anchors.top: parent.top`); the semantic change is never called out.
- `models-delegates` solution uses `pragma ComponentBehavior: Bound` (`page.tsx:749`) — never explained.
- `connected-geometry` anatomy block (`page.tsx:1188-1195`) is **not valid QML** (bare top-level statement), the only non-compilable "read working QML" example.
- `MouseArea`, `TapHandler`, `HoverHandler`, `DragHandler`, `Region`, `ExclusionMode` are used in checks/solutions but appear in **zero** glossary `terms` entries (grep-verified).

## B. The checks themselves are broken

### B1. Universal comment cheat
Checks compile to `pattern.test(code)` on the **raw editor text** (`page.tsx:79`, `page.tsx:1523`, `page.tsx:1981`) — comments/strings are not stripped (unlike `analyzeQml`, which strips them but only for its own diagnostics). **Every mastery gate in the course can be passed by pasting the required tokens into a `//` comment.**

### B2. Correct code fails; wrong code passes
- `reactive-bindings` check 2 (`page.tsx:298`) is order- and line-sensitive: writing `color:` before `width:`, or wrapping a ternary across lines, fails semantically correct code.
- `config-persistence` check 3 (`page.tsx:1111`) fails a learner who writes `// password: intentionally not persisted` — the diligent behavior the lesson asks for.
- `lazy-performance` check 2 (`page.tsx:1329`) is just `/active\s*:/` — any unrelated `active: true` passes.
- `component-contracts` check 3 (`page.tsx:535`) is satisfied by `signal activated` plus a comment containing `activated(`.

### B3. editor.ts "structural QML diagnostics" oversold
Bracket/paren balance checking (comment- and string-aware) is real (`editor.ts:21-49`). But the semantic checks run on comment-stripped-only text — **string contents are not stripped** (`editor.ts:55`) — so `text: "Item { fake }"` passes the root-object check and `text: "id: root"` can trigger false duplicate-id errors. No parser, no AST, no import/type resolution.

## C. Quizzes are pattern-gameable
`quizBank()` (`atlas.ts:828-900`): 6 fixed question templates for all 134 quests, with **literally identical distractor strings across quests per format** (e.g. every mental-model question uses the same 3 wrong answers, `atlas.ts:841`). The correct answer is text the learner just saw verbatim in the lesson pane. Answer position is deterministic: `(questIndex + questionIndex) % 4` (`atlas.ts:817-826`). After a handful of quests a learner can answer by distractor recognition without reading the question. The README's "six authored quiz signals" claim (`README.md:15`) is false for the atlas quests. The legacy quiz distractor bank (`page.tsx:1591-1599`) has the same generic-filler problem in milder form.

## D. The Forge doesn't assemble the learner's work
- `createForgeProject` defaults to a fixed ~2000-line canned scaffold (`forge.ts:398-2426`); learner sources are used only when `applyLearnerSources: true` is explicitly passed (`forge.ts:2531`) — the code's own docs admit this (`forge.ts:2521-2524`).
- Only **13 of 160 quests** are wired to any Forge artifact (`forge.ts:80-206`), all from the legacy 26. Completing any of the 134 atlas quests changes **zero project files** — just a manifest entry (`forge.ts:2474-2479`).
- Tests only exercise the canned path (`tests/rendered-html.test.mjs:149-179`); the "assembled from what you built" promise is never tested because it isn't true by default.
- The scaffold QML itself is idiomatic Quickshell — the code is fine, the claim is false.

## E. "From zero" prior-knowledge gaps (legacy quests)
Never explained anywhere, yet required:
- `!` negation (first required in quest 4; reused in 9, 10, 11, 21).
- `//` comments (used from quest 1's anatomy onward).
- Typed function syntax `function f(): void` (checks in quests 7, 17, 22, 24, 26); "void" never defined.
- `?.` and `??` (`page.tsx:985`), `===` (`page.tsx:1057`), arrow functions + `Array.find` (`page.tsx:1057`), `Math.max/min` (`page.tsx:1251-1282`), hex color literals (quest 1 onward).
- "Compositor", layer-shell concepts, and **"Hyprland" named with zero definition** (`page.tsx:1122`).
- The `qs.modules.*` import alias (`page.tsx:836-839`) — never explained.
- **No toolchain lesson at all**: nothing on installing Quickshell, running `qs`, or that `shell.qml` lives in `~/.config/quickshell/` — despite that being the course's end goal.
(Counter-example done right: the ternary operator *is* explained in anatomy notes, `page.tsx:263`.)

## F. UI/usability of the lesson flow
Good: check labels visible from the start in split mode; persistent Hint button; solution one click away; hint/solution use tracked into mastery instead of hard-punished.

Problems:
- **`build` mode hides all teaching content** (`globals.css:515` hides quest rail + lesson scroll) — a beginner who clicks the intuitively-named "build" is stranded with only check labels; this directly produces the "clear conditions with no explanation" experience.
- Semantic check failures carry **no line numbers** (`page.tsx:2411,2415`) — only syntax diagnostics do (`page.tsx:2410`).
- Hidden second gate: "Claim +XP" additionally requires 3/3 on the PREDICT quiz (`page.tsx:2418`), unannounced in the objective — passing all code checks looks like completion but isn't.
- Hint ladder is binary (one-line label hint → full solution); the DEVELOPMENT_PLAN's promised 5-tier ladder doesn't exist.

## G. Misc
- `examples/forge-starter/` is stale and orphaned: `shell.qml` never imports the four singleton files sitting next to it; no `qmldir` exists, so the singletons can't resolve as a module; its README claims a `practice/` behavior that doesn't exist in `forge.ts`; nothing in the repo references the directory.
- Marketing copy (`layout.tsx`) advertises "160 interactive quests… Learn from absolute zero" — see A/E.
- `DEVELOPMENT_PLAN.md` already admits several of these problems (regex gates cheatable, templated quiz signals, canned Forge scaffold) — the plan is honest; the shipped product and README are not.
- Progress storage: one-way v2→v5 key migration (`page.tsx:1633-1634`, `page.tsx:2018`) — benign.
- `mastery.ts` is the one genuinely sound engine piece: real spaced-review scheduling (4h→2d→7d→21d ladder), accuracy/streak/confidence blend, actually consumed by review selection and covered by tests. Intervals are ad hoc rather than a cited algorithm, but it works.

## Priority fix order
1. **Strip comments/strings before running checks** (reuse `analyzeQml`'s `meaningful` text) — closes the universal cheat (B1).
2. **`reactive-bindings`**: teach `MouseArea`/`onClicked`/`!` in the quest, or drop check 3 (`page.tsx:298`) — the worst single explanation gap, on a boss gate.
3. **Give every quest a "clear conditions" panel in ALL modes** — never hide the lesson content in build mode; add line-anchored feedback for failed checks.
4. **Stop sharing recipes across unrelated quests**, or at minimum make blueprints carry their own checks (`Blueprint` needs a `checks` field) so a battery quest checks battery code.
5. **Fix or drop the quiz generator**: per-quest distractors, randomized answer positions, questions not answerable by template recognition.
6. **Either wire the Forge to learner work by default or change the copy** — "the artifact produced here becomes part of the same persistent shell" is currently false for 147 of 160 quests.
7. Add a JS-for-QML micro-track (comments, `!`, `===`, `?.`/`??`, arrows, `Math`, hex colors, `void`) and a Quickshell toolchain/setup quest before quest 14.
8. Introduce every identifier a check requires in that quest's glossary (`MouseArea`, `TapHandler`, `Region`, `ExclusionMode`, …).
9. Delete or rebuild `examples/forge-starter/`; fix the invalid `connected-geometry` anatomy block (`page.tsx:1188-1195`).
